# 修練 — 開發路線圖（ROADMAP）

分兩批實作，但**第一批就要替第二批預留好資料欄位與畫面位置**（見 CLAUDE.md 的擴充性原則）。

| 批次 | Phase | 內容 |
|---|---|---|
| 第一批（第一個每天可用的版本） | 0 | 地基：技術驗證 |
| | 1 | 功課與打卡 |
| | 2 | 修仙核心 |
| | 3 | 提醒與動態島 |
| | 4 | 玉簡、壽元與續命補簽 |
| | 5 | 學習計時器與修煉週報 |
| 第二批 | 6 | 寶物與經濟 |
| | 7 | 成就與錦上添花 |

正式美術不屬於任何 Phase，可以隨時分批導入（見文末「隨時：美術導入」）；在那之前一律用佔位版本。

每個 Phase 完成的定義：

- CI 通過，合併到 main
- 我在手機上照「驗收清單」逐項測過

## 每個 Phase 的開場指令（貼給 Claude Code）

```
請先讀 CLAUDE.md，再讀 docs/ROADMAP.md 的 Phase N，以及它引用的規格章節。
先用計畫模式列出你要做的事、會新增或修改的檔案，等我確認後再動手。
完成後開 PR，用 gh 等 CI 通過，再告訴我手機上要怎麼測。
```

## 順序的理由

1. **Phase 0** 先驗證最有風險的技術：免費帳號下的動態島、動態島按鈕、排程啟動、兩個 activity 同時存在、讀取簽章到期時間。
   任何一項不行，就要在寫大量程式之前改設計。
2. **Phase 1–2** 讓 app 可以每天用，而且一開始就有遊戲感。
3. **Phase 3–4** 處理提醒、動態島、備份與重新簽章。第一次重簽在安裝後 7 天內就會發生，所以續命補簽排在前面。
4. **Phase 5** 是第一版的加分功能。
5. **第二批**加深遊戲內容。

## Phase 1：功課與打卡

**範圍**

- 資料層：`AppState` 存成 JSON，寬容解碼，由單一 store 管理；第二批的欄位先保留（SPEC 第 12 節）。
- `XiulianCore`，全部附單元測試：
  - 日期歸屬（換日 04:00）、補登、結算（依日期順序、可一次補算多天）
  - 身分門檻檢查（最少項數、學習要求）
  - 計入份量、三分之二達標、圓滿
  - 運動休息規則：可休息／每天都要練、連休天數、今日該練（計入份量）
  - 定課鎖定（之後的修改從明天生效）、功課快照
  - 閉關暫停：每月 5 天上限、預約與取消、不能補申請
- 入門流程的簡化版：道號 → 身分 → 立下功課（依身分的範本）→ 丹房（可略過）→ 通知權限。
- 功課管理：
  - 計分功課：學習（完成型／時數型）、運動（休息規則）、習慣；欄位見 SPEC 2.2。
  - 定時補充：欄位見 SPEC 2.3。
  - 數量與身分門檻的檢查。
- 今日頁：
  - 勾選與取消；時數型學習的時數輸入；運動分鐘的快速選擇
  - 進度環（標出三分之二）、「還差 N 份量」、必做尚缺提示、定課提示
  - 運動顯示「可休息」與連休天數，或「今日該練」
  - 丹房：補充時段打勾
  - 閉關暫停按鈕；昨日補登分頁
- 修煉日曆：簡易月曆，用顏色區分未達標、達標、圓滿，暫停日用圖示。
- 設定：更換身分（14 天冷卻、下一次換日生效）、換日時間、補登截止、閉關暫停預約。
- 每日自動封存玉簡到 Documents/玉簡/（SPEC 7.4 第一列）；設定頁的「立即封存」。
- 開發者工具：測試模式（沙盒）加上時間旅行（SPEC 第 11 節）。

**手機驗收**

- [ ] 選「自學」→ 只建 4 項計分功課無法儲存；學習目標合計不到 3 小時也無法儲存
- [ ] 凌晨 01:30 勾選的功課，算在前一天；04:00 之後才換成新的一天
- [ ] 清單「學習、運動（每天練）、習慣」：漏學習 → 未達標（50%）；漏運動 → 剛好三分之二，達標（顯示 66%）
- [ ] 再加兩個簡單的習慣，漏掉學習 → 仍然未達標（62%）
- [ ] 必做沒完成時，就算超過三分之二也不算打卡
- [ ] 可休息的運動：連休 0–1 天時不做也能打卡，而且不計入份量
- [ ] 測試模式連續 2 天不運動 → 第 3 天顯示「今日該練」，運動計入份量；沒做、但其他都完成時，剛好三分之二仍然達標
- [ ] 時數型學習目標 2 小時：記錄 1.5 小時 → 還沒完成；再 +0.5 → 自動完成
- [ ] 丹房打勾不影響今日日課的百分比
- [ ] 第一次勾選後新增一項功課 → 提示「明天生效」，今天的清單不變
- [ ] 申請今天閉關暫停 → 今天不能勾選、日曆顯示暫停；本月第 6 天無法申請；不能申請昨天
- [ ] 測試模式：時間旅行到隔天 09:00 → 有「昨日」分頁，可以補勾；旅行到 12:01 → 分頁消失，昨天已結算
- [ ] 時間旅行 3 天不操作 → 3 天都被補算成未達標，日曆顏色正確
- [ ] 離開測試模式 → 正式資料沒有被動到
- [ ] 安裝新版（覆蓋安裝）→ 功課和紀錄都還在
- [ ] 「檔案」App →「我的 iPhone」→「修練」→「玉簡」看得到備份檔

## Phase 2：修仙核心

**範圍**（GAME_DESIGN 第 3–10 節）

- 入門加上測靈根（選五行、抽資質、可重測一次）與選擇周天。
- 修為：
  - 日課池（最大餘數法，總和剛好 100）、苦修（身分係數、遞減與上限）、運動分鐘、定時補充微量

  - 修為公式與「修為明細」
- 靈石：日課靈石池、達標與圓滿獎勵（坊市在第二批）。
- 屬性（神識、體魄、道心、元氣、氣運）、每日上限、效果顯示。
- 境界表、瓶頸池、升級動畫。
- 閉關天數（長期）與里程碑；周天（短期 7／14 日）與每輪獎勵。
- 替身符：
  - 昨天未達標時，今日頁出現提示視窗；可以用背包裡的，或直接用靈石購買
  - 時窗（隔天之內）、價格遞增、持有上限
  - 替身日的效果：保住閉關天數，周天歸零，渡劫失敗
- 走火入魔（GAME_DESIGN 9.5）：扣小境界上限的 5%、根基不穩、跌落小境界、大境界不跌落。
- 閉關暫停的遊戲效果：閉關天數、周天、運動連休天數、渡劫進度凍結。
- 重拾道心。
- 渡劫：開始、天雷進度、成功與失敗、暫停時凍結、動畫、成功獎勵（GAME_DESIGN 8.3）。
- 首功寶箱與今日機緣：祝福、限時挑戰（倒數、進度、達成動畫）、意外之財。
  意外之財的「隨機物品」在第二批補上，之前先改給靈石。
- 背包的最小版本：丹藥與符籙（聚氣丹、替身符、突破丹藥等），可以使用。
  寶匣類獎勵先放進儲物袋，第二批才能開啟。
- 道體頁；寶庫頁的坊市與圖鑑先顯示「即將開放」。
- `ArtAsset` 與佔位版本（CLAUDE.md「美術」一節）：立繪、境界徽章、寶箱、道具；已經導入的正式圖直接使用。
- 新手禮包：聚氣丹 ×3、替身符 ×1。

## Phase 3：提醒與動態島

**範圍**（SPEC 第 4、5 節）

- 四個檢查點：預設 16:00、19:00、21:00、23:00，可以改時間或停用。
- 只在當天還沒達標時發送；達標或暫停時取消今天剩下的檢查點。
- 內容：缺少的必做、還差份量、今日該練、丹房未服、替身符提示、23:00 提到閉關與周天。
- 師父傳音文案庫：每個時段至少 5 種，時辰要正確。
- 排程：今天加未來 6 天、identifier 規則、各種重排時機。計算部分放在 `XiulianCore` 並附測試。
- 每日進度 Live Activity：
  - 版面：compact（日課百分比）、minimal、expanded、鎖定畫面、慶祝樣式
  - 按鈕：一般功課「完成」、時數型學習「+0.5 小時」
  - 21:00 排程啟動、23:00 緊急樣式、倒數到 04:00、換日後結束、達標或暫停時取消
  - 今日頁的「顯示於動態島」按鈕
- 開發者工具：列出已排程的通知、立即觸發指定檢查點、把動態島的排程改成 2 分鐘後、檢視 pending 和 active 的 activity。

**手機驗收**

- [ ] 開發者工具列出的通知只有檢查點（最多 28 則）和壽元警告
- [ ] 16:00 的通知列出了未完成的功課與「還差 N 份量」；丹房沒吃的也有提到
- [ ] 達標後，今天剩下的提醒全部消失，動態島也不會再出現
- [ ] 昨天未達標時，今天的提醒有提到替身符
- [ ] 可以休息的日子，提醒不會把運動列為缺少；今日該練時會提到
- [ ] 23:00 的文案有提到閉關天數和周天進度
- [ ] 21:00（或用開發者工具改成 2 分鐘後）動態島自動出現，並跳出師父傳音
- [ ] 展開後看得到境界、閉關天數、周天進度；倒數是到 04:00
- [ ] 在動態島或鎖定畫面按「完成」或「+0.5 小時」，進度即時更新
- [ ] 21:00 前就達標，或今天暫停 → 21:00 不會出現
- [ ] 過了 23:00 → 變成「子時已至」的緊急樣式
- [ ] 換日後打開 app → 前一天的 activity 被結束

## Phase 4：玉簡、壽元與續命補簽

**範圍**（SPEC 第 7 節）

- 壽元顯示（命燈）、到期前 30 小時與 6 小時的通知。
- **第 6 天自動打包**（每個簽章週期一次），並寫到外部資料夾。
- 外部備份資料夾：選擇、bookmark、失效處理、`修練玉簡_最新.json` 每日覆寫。
- 讀取玉簡：預覽摘要、還原前自動封存、還原後重排。
- 續命偵測與延壽丹獎勵。
- **續命補簽**（SPEC 7.6）：集中在一個可以拔除的模組，有設定開關；結算遇到待補簽的日子要停住。
- 說明頁「資料什麼時候會不見」（SPEC 7.1）。
- 開發者工具：模擬壽元剩 25 小時、模擬 app 過期 2 天後重新簽章。

**手機驗收**

- [ ] 選擇 iCloud 雲碟的資料夾 → 隔天打開 app，資料夾裡有 `修練玉簡_最新.json`
- [ ] 模擬壽元剩 25 小時 → 自動產生帶日期的玉簡（app 內和外部資料夾都有）
- [ ] 重新簽章 → 打開 app 顯示「續命成功」，拿到延壽丹
- [ ] 模擬過期 2 天後重簽 → 出現補簽頁，可以補記那 2 天；也可以改用替身符或暫停額度；3 天後沒補的照一般規則結算
- [ ] 關掉續命補簽開關 → 過期的日子照一般規則結算
- [ ] 測試模式中讀取一份舊玉簡 → 摘要正確 → 還原後資料一致
- [ ] 壽元剩不到 1 天時，命燈變紅

## Phase 5：學習計時器與修煉週報

**範圍**（SPEC 第 6 節）

- 學習計時器：開始、暫停、繼續、結束；計時器 Live Activity 與按鈕；確認畫面（只能改短）；單次 4 小時上限；跨換日算開始那天；app 被關掉不遺失。
- 計時加成：計時記錄的時數，苦修修為多 10%（GAME_DESIGN 5.2）。
- 修煉週報：週一換日後第一次打開 app 時顯示、內容、和前一週比較、下週小目標、達成時靈石 +100、道體頁回看。
- 開發者工具：計時器快轉、立即產生上週的週報。

**手機驗收**

- [ ] 開始計時後鎖定手機 → 動態島顯示經過時間；按暫停會停住
- [ ] 把 app 從背景滑掉再打開 → 計時還在
- [ ] 結束時可以把時間改短，不能改長；記入後浮字顯示 +10% 計時加成
- [ ] 快轉超過 4 小時 → 只記 4 小時
- [ ] 計時中同時有每日進度的動態島 → 兩個都正常
- [ ] 產生上週的週報 → 數字和日曆、修為紀錄一致；下週小目標合理
- [ ] 達成下週小目標 → 下一次週報結算時拿到靈石 +100

## 隨時：美術導入

正式圖由我用 AI 生成並檢測後，分批放進 `art/masters/`（流程見 ART_ASSETS 第 0 節與第 8 節）。
我說「導入美術」時做這件事，可以穿插在任何 Phase 之間，一批開一個 PR。

**範圍**（CLAUDE.md「美術」一節）

- 執行 `tools/check_art.py`，只導入通過的圖；不通過的列出原因。
- 第一次導入時建立 `tools/import_art.py`：依 manifest 的 `display` 產生 @2x、@3x，寫進 asset catalog。
- App 圖示寫進 AppIcon；境界徽章另外產生小尺寸給 widget extension。
- 把對應的佔位版本換成正式圖，並套上 ART_ASSETS 第 1 節的特效。

**手機驗收**

- [ ] 這次導入的圖出現在對應的畫面，不模糊、沒有鋸齒，邊緣沒有白邊或灰邊
- [ ] 還沒導入的圖照樣顯示佔位版本，沒有空白或錯誤

- [ ] 換了境界徽章時：動態島展開畫面與鎖定畫面顯示正式徽章
