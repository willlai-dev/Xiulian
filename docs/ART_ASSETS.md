# 修練 — 美術製作規格（ART_ASSETS）

> 給「AI 生圖 → AI 檢測 → Claude Code 導入」的流程使用。
> 這份文件由 `tools/build_art_doc.py` 依 `art/manifest.json` 產生。要修改清單或提示詞，請改 manifest 後重新執行 `py tools/build_art_doc.py`，不要直接改這份文件。

## 0. 分工與流程

| 角色 | 負責 |
|---|---|
| 你 | 用生圖 AI 一張一張生成；需要時去背、轉成 PNG、改檔名 |
| 檢測 AI | 依第 5 節的標準逐項檢查，給出通過或不通過 |
| Claude Code | 用程式檢查技術規格、縮放並放進 app、用程式做所有動態特效 |

每一張圖的流程：

1. 複製這張的「生成提示詞」（第 9 節）貼給生圖 AI，並附上同類的基準圖（第 3.6 節）。
2. 不滿意就重新生成；同一張最多試 5 次，還是不行就把檢測結果貼給 Claude，請它修改提示詞。
3. 需要去背的圖，去背後存成 PNG（第 4.3 節）。
4. 改成清單上的檔名，例如 `item_bt_zhuji.png`。
5. 開一個檢測 AI 的對話，先貼一次「檢測 AI 開場設定」（第 5.3 節）；之後每一張貼上它的「檢測卡」，並附上圖片。
6. 通過的圖放進 repo 的 `art/masters/`，在第 9.1 節的總表打勾。想先確認尺寸與透明背景，可以自己跑技術檢查（第 8 節）。
7. 累積一批後告訴 Claude Code：「導入美術」，它會接手（第 8 節）。

## 1. AI 只畫靜態主圖，特效交給程式

AI 生成的圖一律是**靜態、乾淨的主體**。不要在圖裡畫光暈、光束、粒子、煙霧、閃電這類特效：
這些由程式疊加，才能做成動畫、依品質換顏色，也比較好去背。

| 圖片 | 程式會加上的效果 |
|---|---|
| App 圖示 | 無（靜態圖示） |
| 角色立繪 | 境界色光環、待機時上下浮動、元嬰虛影（把立繪縮小、半透明疊在身後）、渡劫雷光、升級爆光 |
| 師父插圖 | 對話框、淡入淡出、說話時輕微浮動 |
| 境界徽章 | 外圈旋轉光暈、解鎖時爆光、還沒達到的境界顯示灰階 |
| 寶箱 | 搖晃與震動、品質色光柱、粒子、開箱閃光、物品飛出 |
| 道具圖示 | 品質色光暈與外框、漂浮、光澤掃過、獲得時彈跳放大 |
| 介面道具 | 紙人燃燒、線香的煙與香頭火光、命燈火焰（依壽元變化）、淡入 |
| 空白卷軸 | 由上往下展開的動畫、文字排版 |
| 背景 | 雲霧緩慢飄動、月光微微明暗、渡劫的閃電與雲層翻湧 |
| 法寶 | 品質色光暈與外框、漂浮、光澤掃過、獲得時彈跳放大 |
| 功法秘笈 | 品質色光暈、書名文字（程式排版）、翻開動畫 |
| 靈根靈珠 | 外發光、旋轉、測靈根時的抽選動畫 |
| 卡片背面 | 翻牌動畫、邊緣光澤 |

完全由程式繪製、不需要圖片的東西：進度環、修為條、周天念珠、天雷與閃電、浮字、品質外框與光暈、所有文字。

- 先寫成看不出性別的修士，方便以後分享給朋友。想改成明確的男性或女性角色，請 Claude 修改 manifest 的角色設定。

## 4. 技術規格

### 4.1 檔案

- **檔案類型**：PNG；背景圖也可以用 JPG（品質 90 以上）。不要 WebP、HEIC、PSD、SVG。
- **色彩**：8 位元、sRGB。工具輸出 Display P3 或 16 位元時，請轉成 8 位元 sRGB。
- **尺寸**：不能小於規格；可以更大，但比例要一樣（例如 2048×3072）。
- **檔名**：照清單的 id，全小寫英文與底線，例如 `item_bt_zhuji.png`。
- **檔案大小**：單張 5 MB 以內；太大可以用 TinyPNG 之類的工具壓縮。
- **重做**：同一張要重做時，用相同檔名覆蓋。
- **縮圖**：你不需要做縮圖或多種尺寸，Claude Code 會依畫面需要產生。

### 4.2 各類別的規格

| 類別 | 比例與最小尺寸 | 主體大小 | 交付 |
|---|---|---|---|
| App 圖示 | 正方形 1:1，1024×1024 | 約 70% | PNG（不透明，不能有透明通道） |
| 角色立繪 | 直式 2:3，1024×1536 | 高度約 90% | 透明 PNG |
| 師父插圖 | 直式 2:3，1024×1536 | 下緣切在腰部 | 透明 PNG |
| 境界徽章 | 正方形 1:1，1024×1024 | 直徑約 90% | 透明 PNG |
| 寶箱 | 正方形 1:1，1024×1024 | 寬度約 75% | 透明 PNG |
| 道具圖示 | 正方形 1:1，1024×1024 | 約 65% | 透明 PNG |
| 介面道具 | 正方形 1:1，1024×1024 | 約 65% | 透明 PNG |
| 空白卷軸 | 直式 2:3，1024×1536 | 高度約 90%（含木軸） | 透明 PNG |
| 背景 | 直式 2:3 或更長的直式（例如 9:16），1024×1536 | 整張場景 | PNG 或 JPG（不透明） |
| 法寶 | 正方形 1:1，1024×1024 | 約 75% | 透明 PNG |
| 功法秘笈 | 正方形 1:1，1024×1024 | 約 70% | 透明 PNG |
| 靈根靈珠 | 正方形 1:1，1024×1024 | 約 70% | 透明 PNG |
| 卡片背面 | 直式 2:3，1024×1536 | 填滿畫面 | PNG（不透明） |

### 4.3 去背

- **生成時**：用每張規格指定的純色平塗背景，純白（#FFFFFF）或中性灰（#808080）；淺色的主體用灰色比較好去背。
  工具能直接輸出透明背景 PNG 的話，也可以直接要求透明背景。
- **去背工具**：Windows 11 小畫家的「移除背景」（免費，保留原尺寸），或 Photoshop 等影像軟體。
  小畫家：開啟圖片 → 按工具列的「移除背景」→ 放大檢查邊緣，需要時用橡皮擦修 →「另存新檔」選 PNG。
- **畫布維持原尺寸**：去背只是把背景變透明，不要裁切或縮小。線上去背服務的免費版常會把下載的圖縮小（例如只給約 625×400 的預覽），手機內建的去背也可能把畫布裁到只剩主體；這兩種都會不符合尺寸與留白。
- **去背後確認**：
  - 四個角落完全透明。
  - 主體邊緣沒有殘留白邊或灰邊，也沒有鋸齒。
  - 主體和背景之間的空隙要透明，例如兩腳之間、手臂和身體之間。
  - 主體本身沒有被挖掉，例如白色衣服、白色花紋都還在。
  - 沒有殘留的影子或背景碎片。
- **不需要去背**：App 圖示、背景、卡片背面。

## 5. 品質檢測標準

### 5.1 技術檢查（程式負責）

檢測 AI 看不出精確的像素尺寸與透明通道，所以這部分由程式檢查。
Claude Code 導入前會執行 `tools/check_art.py`；你也可以自己先跑（見第 8 節）。
各類別的最小留白與主體大小範圍，寫在 `art/manifest.json` 每個類別的 `check` 欄位。

| 項目 | 標準 | 不符合時 |
|---|---|---|
| 檔名 | 和清單的 id 完全相同（全小寫）；同一張圖只有一個檔案 | 不通過，並提示可能的正確檔名 |
| 檔案類型 | PNG（背景可以是 JPG）；副檔名和實際格式一致 | 不通過 |
| 尺寸與比例 | 不小於規格，比例誤差 1% 以內 | 不通過 |
| 色彩 | RGB、8 位元、sRGB | CMYK 不通過；16 位元或色彩描述檔不是 sRGB 提醒 |
| 透明 | 去背類要有透明背景；App 圖示、背景、卡片背面不能有透明的地方 | 不通過 |
| 四個角落 | 去背類完全透明 | 不通過 |
| 主體位置 | 和畫布邊緣保持該類別的最小留白（師父插圖的下緣可以切齊畫面） | 不通過 |
| 主體大小 | 在該類別的建議範圍內 | 提醒 |
| 殘留背景色 | 主體最外圈沒有大量白邊或灰邊 | 提醒 |
| App 圖示四角 | 不是純白（圖示要整張填滿，圓角由 iOS 裁切） | 提醒 |
| 檔案大小 | 5 MB 以內 | 提醒 |

|---|---|---|---|

| 4 | 構圖完整 | 必須 | 主體的位置與大小符合規格；主體完整，沒有被畫面邊緣切到（立繪要包含雙腳）。 |
| 5 | 背景乾淨 | 必須 | 需要去背的圖：背景是乾淨的單色平塗（或已經是透明），沒有地面、影子、漸層或雜物；去背後邊緣沒有白邊或灰邊。 |
| 6 | 結構正確 | 必須 | 人物五官端正、手指數量正確、沒有多出或缺少的肢體；物品結構合理，該對稱的地方對稱。 |
| 7 | 沒有 AI 瑕疵 | 必須 | 沒有扭曲、融化、重複或莫名其妙的細節；沒有明顯的雜訊或模糊。 |
| 8 | 原創且合宜 | 必須 | 不像任何知名遊戲、動畫或品牌的角色與標誌；沒有血腥、暴力、裸露等不適合的內容。 |
| 9 | 風格一致 | 必須 | 和同類基準圖相比，筆觸、配色、光源（左上）與視角一致；立繪必須是同一個角色。基準圖本身這項直接算 PASS。 |
| 10 | 縮小可讀 | 建議 | 縮小到手機上的實際大小（徽章約 64 像素、道具約 128 像素、App 圖示約 60 像素）仍然一眼認得出來。 |
| 11 | 色彩合宜 | 建議 | 主色符合描述（例如品質色）；整體不過度飽和、不偏螢光。 |

### 5.3 檢測 AI 開場設定（每次開新對話時貼一次）

```text
你是手機遊戲「修練」的美術品管。接下來我會一張一張給你圖片和「檢測卡」，請依照下面的標準檢查。

【共通標準】
1. 主體正確（必須）：畫的是「主體描述」中的東西，「必要特徵」全部都有。
2. 沒有文字（必須）：畫面中沒有任何文字、字母、數字、印章字、簽名或浮水印；符紙、令牌、牌坊、書封上的圖案也不能像文字。
3. 沒有特效（必須）：沒有光暈、光束、粒子、煙霧或閃光（背景與 App 圖示除外）。
4. 構圖完整（必須）：主體的位置與大小符合規格；主體完整，沒有被畫面邊緣切到（立繪要包含雙腳）。
5. 背景乾淨（必須）：需要去背的圖：背景是乾淨的單色平塗（或已經是透明），沒有地面、影子、漸層或雜物；去背後邊緣沒有白邊或灰邊。
6. 結構正確（必須）：人物五官端正、手指數量正確、沒有多出或缺少的肢體；物品結構合理，該對稱的地方對稱。
7. 沒有 AI 瑕疵（必須）：沒有扭曲、融化、重複或莫名其妙的細節；沒有明顯的雜訊或模糊。
8. 原創且合宜（必須）：不像任何知名遊戲、動畫或品牌的角色與標誌；沒有血腥、暴力、裸露等不適合的內容。
9. 風格一致（必須）：和同類基準圖相比，筆觸、配色、光源（左上）與視角一致；立繪必須是同一個角色。基準圖本身這項直接算 PASS。
10. 縮小可讀（建議）：縮小到手機上的實際大小（徽章約 64 像素、道具約 128 像素、App 圖示約 60 像素）仍然一眼認得出來。
11. 色彩合宜（建議）：主色符合描述（例如品質色）；整體不過度飽和、不偏螢光。

【判定】「必須」全部 PASS，「建議」最多 1 項 FAIL，才算通過。

【輸出格式】
1. 用表格逐項回答：項目｜PASS 或 FAIL｜說明。
2. 最後一行寫「結論：通過」或「結論：不通過」。
3. 不通過時，具體建議生成提示詞要怎麼改。

我會同時附上同類的基準圖，請用它判斷第 9 項。檢測卡寫「這張就是基準圖」時，第 9 項直接算 PASS。
你看不出精確的像素尺寸與透明通道，這兩項不用判斷，會另外用程式檢查。
```

### 5.4 每張要給檢測 AI 的東西

1. 這張的「檢測卡」文字（第 9 節）。
2. 要檢測的圖：去背類給去背後的 PNG；App 圖示與背景直接給原圖。
3. 同類的基準圖（基準圖本身不用）。

## 6. 生成提示詞的結構

第 9 節每一張的「生成提示詞」都已經組好，可以直接複製。結構如下，方便你需要時自己調整：

```text
請畫一張〔用途〕。
角色：〔只有立繪有〕
```

## 7. 常見問題與修正方式

「加上」是指加在生成提示詞的最後一行。

| 問題 | 修正方式 |
|---|---|
| 圖裡出現文字或像文字的符號 | 加上「畫面中完全不要有任何文字、字母、數字，也不要像文字的筆畫」 |
| 出現光暈、煙霧或閃光 | 加上「不要任何發光、光暈、煙霧或粒子效果，主體邊緣要乾淨俐落」 |
| 主體被裁切或太靠近邊緣 | 加上「主體完整入鏡，四周保留空白」 |
| 主體太大或太小 | 加上「主體約佔畫面的 N%」（N 照這張檢測卡的「主體大小與位置」） |
| 背景有地面、影子或漸層 | 加上「純色平塗背景，沒有地面、沒有影子、沒有漸層」 |
| 立繪換了一個人 | 附上 `avatar_realm_1`，並加上「和附圖是同一個角色，臉、髮型、身形完全一樣，只換服裝與配件」 |
| 手指或肢體怪異 | 加上「手部自然、五根手指、比例正確」，或改成「雙手藏在袖子裡」 |
| 和其他圖的畫風不一致 | 附上同類的基準圖，並加上「沿用附圖的筆觸、配色、光源與視角」 |
| 顏色太鮮豔或偏螢光 | 加上「色調沉穩，降低飽和度」 |
| 物品不是單獨一個 | 加上「畫面中只有一個物件，不要其他物品或裝飾」 |
| 視角不對 | 加上「3/4 俯視角，大約從上方 30 度往下看」 |

## 8. 交付給 Claude Code

- **放置位置**：repo 的 `art/masters/<id>.png`（背景也可以是 `.jpg`）。
- **重做**：用相同檔名覆蓋。
- **通知**：告訴 Claude Code「導入美術」，或列出這次的檔名。它會：

  3. 把對應的佔位圖換成正式圖，並在 PR 的手機測試步驟裡說明要看哪裡。
